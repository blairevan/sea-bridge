## 已修复问题

### P2：快速切换筛选时最新选择被丢弃

位置：src/web/public/app.js 的筛选事件及 run 调用。

原先全部筛选复用 sessions 操作锁。Desktop 请求未完成时切换 CLI，新请求被锁拦截；旧响应又因筛选不匹配被丢弃，页面继续显示旧结果，直到后续刷新。改为按来源、创建来源、状态、搜索词组成独立读取键，保留同条件重复请求抑制及过期响应检查。发送操作锁不变。

回归使用实际筛选事件绑定，控制两个请求的完成顺序，验证新条件发出请求且旧响应不会覆盖结果。

### P2：当前会话不在列表结果中时，恢复后发送按钮持续禁用

位置：src/web/public/app.js 的 loadSessions。

断线会把选中会话的 sendEnabled 设为 false。原先只从当前列表恢复，独立查询仅适用于刚创建的会话。选中会话被筛选条件排除或落在其他分页时，恢复连接仍无法发送。

现在对列表以外的选中会话，按原 source 和 sessionId 单独读取，更新真实发送能力；查不到时保持禁止发送，并保留身份及隐私版本竞态检查。

### P2：超过最近 100 条消息的附件无法加载

位置：src/web/sources/codex.ts、src/web/codex-transcript.ts。

原先附件接口只在最近 100 条消息中查找，即使用户已通过历史翻页看到更早消息，也会返回附件不存在。

现在按原生消息的字节偏移读取对应记录。共用原有根目录隔离、普通文件、O_NOFOLLOW 与 inode/dev 校验；偏移必须为安全整数和完整行起点，每次记录读取最多 256 KiB，附件仍由原用户消息和所属附件目录授权。测试覆盖 110 条后续消息、伪造偏移、路径逃逸、截断与超长记录。

### P2：原生数据库路径错误会创建空数据库

位置：src/desktop/codex-thread-store.ts。

读取连接使用 SQLite 默认创建模式；路径失效时会留下空数据库后再报缺表。两个入口均改用 readonly: true，路径缺失直接失败。回归分别检查列表和单条查询失败后没有创建文件。当前 Mac 原生数据库只读查询亦成功。

# 会话状态补证与一致性修复

## 目标与范围

来源为用户直接输入：“按这个方案修复，一镜到底”。本任务修复列表与详情的状态判定、刷新和不确定态展示。仓库没有定义额外的“一镜到底”远端交付链；按 SIR 变更流程完成研发验证，不操作已运行服务、生产数据库或推送既有本地提交。

任务会话 `01a1afad-1eba-74e0-bef9-257289f3333b` 已通过宿主工具改名为“修复会话状态未知与列表刷新机制”并回读。未启用 SIR 控制器或修改 hooks。基线为 `d385809`，实现分支为 `codex/session-status-reconciliation`；开始时工作区干净，main 比 origin/main 领先三个既有提交。

## 根因及方案

- 列表依赖后台观察器及仅由详情读取建立的 10 秒缓存。未确认的 `interrupted` 会落为 unknown，缓存失效后再次出现未知。
- 新增 `src/web/session-activity.ts`：集中解析本地轮次记录及只读最新轮次查询；按文件路径、inode、大小和修改时间缓存，列表与详情共用；限制缓存条数、并发查询和等待时间。
- 仅对请求页或精确会话主动补证。轮次 ID 和时间共同约束证据选择；不允许旧轮次终态覆盖新轮次，也不凭一个旧 started 推断仍在运行。
- 未确认的中断不作为终态。显示“正在确认”，30 秒后仍不收敛则显示“暂无法确认”，继续按间隔补证。失败保留上次已确认状态作为展示上下文，不作为当前状态或操作权限。
- 不确定原因使用稳定枚举保存于响应；列表、概览与详情共用展示文案。会话列表增加手动刷新入口。
- 不改变执行验收、队列恢复、模型更新或中断授权判定，也不改写观察器数据库中的原始证据。
